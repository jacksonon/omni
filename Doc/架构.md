## 1. 定位

Omni 是一个 **Agent 工程**（终端型 AI 编程助手）。技术栈为
TypeScript strict · ESM（NodeNext）· 裸 `openai` SDK · `@opentui/core`（命令式渲染）· 无框架依赖。

设计理念：

- **认知优先**——代码是认知梳理对话的落地，保持最小可读，不为「架构好看」引入抽象；
- **可替换后端**——`OMNI_BASE_URL` 兼容所有 OpenAI 协议的服务（OpenAI / DeepSeek / 智谱 / Moonshot / Grok 等）。

Agent 本体**不依赖任何框架**：裸 OpenAI SDK + 主循环。

## 2. 分层总览

```
   入口层   index.ts (CLI)  ──  exec.ts (headless)  ──  web/index.ts  ──  tui-entry.ts
              │                     │                        │                  │
   运行时层 main.ts attachRuntime（安全闸门 + MCP 发现 + delegate 注入 + 上下文准备）
              │                     client.ts（按模型端点建客户端，/model 切换端点时重建）
              ▼
   Agent 层   agent/loop.ts ──  context.ts（记忆/预载/压缩） ──  subagent.ts（隔离嵌套）
              │                     │
   工具层     tools/*（静态 7 个 + 运行时注入 delegate / mcp_*）
              │
   安全层     safety/（权限分级 · 审批 · 审计 · 工作区信任 · OS 沙箱）   hooks/（生命周期）
              │
   输出层     output/console.ts  │  tui/output.ts  │  web/output.ts  │  exec（机器可读）
```

四个输出后端是同一个 `Output` 接口的可替换实现——这正是 CLI、TUI、Web 界面与 headless 能共用
一套 Agent 内核的原因。

## 4. 核心循环（src/agent/loop.ts）

```
for step in 1..maxSteps:
  1. 流式调用 LLM（携带全部历史消息 + 系统提示词）
  2. 无工具调用 → 输出最终回答，结束
  3. 有工具调用 → 解析 JSON 参数 → 并行执行（Promise.all）
     · 每个调用先过 Safety 闸门（权限分级 + 审批 + 审计）
  4. 结果按原顺序以 role=tool 回传 → 回到 1
```

关键机制：

- **自我纠错**——工具执行失败/被拒时，错误信息作为工具结果返回给模型，由模型自己修正；
- **安全闸门**——每个工具调用（含 MCP 外部工具与子代理）都过 `Safety.gate`；
- **并行工具**——一次响应的多个 `tool_calls` 并发执行，结果按调用顺序回传；
- **截断**——工具结果超过 8000 字符会被截断并提示「用 read_file 定向获取」，防止上下文被撑爆；
- **防死循环**——`maxSteps` 上限（默认 50；典型任务 15 次内完成）。

## 5. 一次请求的完整链路

```
参数 → 配置（分层：默认值 → 全局 → 项目 → 自定义 → 环境变量 → CLI 参数）
     → createClient（按模型端点创建）
     → prepareRun / attachRuntime
          ├─ Safety 闸门
          ├─ MCP 工具发现（stdio / streamable HTTP）
          ├─ delegate 注入（allowSubagents 时）
          └─ 上下文准备（记忆级联、相关文件预载、repo map、技能清单）
     → Agent 主循环（流式 → 工具 → 回传）
     → Output 实现（console / TUI / web SSE / headless）
```

Hooks 在这条链路的生命周期关键点触发：`UserPromptSubmit` 在 prompt 被模型看到之前、
`PreToolUse` 在每个过闸调用之前、`PostToolUse` 在之后、`Stop` 在 agent 准备收尾时、
`Notification` 在会话完成时。完整 12 个事件见 `使用指导.md` §13。

## 7. 常用开发命令

```bash
npm run dev -- "<任务>"      # 开发运行（tsx）
npm run typecheck            # TypeScript 类型检查
npm run build                # typecheck + tsc + bun 打包单文件 → dist/omni.cjs
npm start -- "<任务>"        # 运行 tsc 产物
npm run mock                 # 本地 mock API 服务器（端口 8787，无 Key 端到端）

npm run dev:tui -- "<任务>"  # TUI 全屏模式（bun + 真实 TTY）
npm run tui:snapshot         # TUI 快照验证（内存渲染断言）
npm run bundle               # 单文件 JS 包
npm run compile              # 原生二进制 → release/omni（bun compile）
npm run bundle:tui           # 打包 TUI → packages/omni-tui/dist
npm run pack:tui             # 版本同步 + bundle + npm pack → omni-tui-<版本>.tgz
npm run pack:tui:compile     # 一键打包 + 原生二进制

npm run dev:web              # Web 服务（默认 http://127.0.0.1:3080，不开浏览器）
npm run web:sync             # 重建 vendor.js + 同步 web/ → src/web/assets.ts
npm run probe:web            # Web 协议 e2e 探针（离线 mock）
npm run electron:dev         # Electron 桌面应用（开发）
npm run electron:build       # electron-builder 打包 → release-electron/

npm run eval                 # 评估：真实 API 跑任务集 + 完成率报告
npm run eval:mock            # 评估：离线 mock（确定性，可进 CI）
npm run test:features        # 特性测试
npm run models:snapshot      # 重建模型能力快照（models.dev）
```

**打包需要 bun**（`bundle` / `compile` / `npm pack` 都会调用它）；开发运行（`dev`）不需要。

构建产物（详见 `release-guide.md`）：`dist/omni.cjs`（单文件 JS，console 版）·
`release/omni`（原生二进制，TUI 版）· `omni-<版本>.tgz`（console npm 包）·
`omni-tui-<版本>.tgz`（TUI npm 包）· Electron 桌面应用（`release-electron/`）。

## 8. 维护约定

修改**架构、模块或命令**时，请在同一改动里更新本文件与 `architecture.md`——它是
`README.md` 和 `AGENTS.md` 共同指向的权威源。新增工具时，同时在 `tools/index.ts` 登记，
并更新手册中的工具表。
